## 2. 配置の基本設計

- **ネコ＝画面の案内役・達成演出**、**小アイコン＝操作の意味の補助**、**正式ロゴ＝ブランド**。役割を混ぜない。
- 画面上のキャラクターは原則各画面に1点だけ。ネコを操作ボタンそのものには使わず、本文とタップ領域を優先。
- UIアイコンは同じシート由来の絵柄をなるべく揃え、静止サイズは24px（補助）・32px（大きめ）・48〜64px（カード）。ネコは72〜152pxを画面別に最適化。
- 文字ラベルを原則残す。画像の読み込みに失敗しても操作可能で、フォーカス・44px目標のタップ領域・スクリーンリーダー説明を維持する。
- ピクセル絵の補間方法は画像ごとに比較。通常の操作素材はnearest-neighbor候補、細線や猫の透明処理は実画像のドット潰れを見て決める。強制的なSVG自動変換はしない。

## 5. 実装分割と格納

**ブランチ／PR**：PR #2の元画像候補と台帳を参照しつつ、PR #3の現行HEADを基点としたアイコン統合用の独立作業ブランチ／Draft PRを用意する。PR #1, PR #2, PR #3 を丸ごと一括マージしない。最終統合順とマージ先はレビュー時に確定する。

推奨：
- `assets/icons/cats/<ID>.png`：厳選ネコの透過画像のみ
- `assets/icons/ui/<ID>.png`：画面で実際に使う操作図柄のみ
- `assets/icons/icon-map.mjs`：既存ID、パス、種別、推奨サイズ、使用先、fallbackを対応付け
- `docs/icons/SCREEN_ASSET_ACCEPTANCE.csv`：ID／元画像SHA256／加工版SHA256／背景透過／最小サイズ視認／UI導線／採否
- バンク196件のフル画像は別保管。アプリ初期ロードに196枚を含めない。候補更新時もIDは固定。

**表示部品**：`<img loading="lazy" decoding="async">` を基本にし、表示必須の先頭アイコンは必要に応じ優先読込。静的要素にはHTML/CSS、JS生成の行・RUNタイマーボタンには描画ヘルパーを使う。存在しないアイコンはテキストと現行CSS/記号に戻す。画像追加の成否で現行状態保存や計算を変更しない。

**ロゴとの競合回避**：既存 `brand-home-slot` とHOMEのネコを同時に大きく表示しない。ブランド採用画像が戻った時点でHOME構図を1枚のスマホキャプチャで比較し、ヘッダーにはロゴ、ヒーローにはネコを置く案を基本とする。正式ロゴの承認ゲートはこのアイコンの作業ではONにしない。
